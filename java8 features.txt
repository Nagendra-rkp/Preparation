filter() is used for filtering records based on a condition, whereas map() is used for transforming one object into another object or value.

filter = Select Data

Map vs FlatMap

Map

Returns one value for one input.

List<String> names =
Arrays.asList("Nagendra","Rahul");

names.stream()
     .map(String::toUpperCase)
     .forEach(System.out::println);
	 
Why flatMap()?

Suppose you have:

List<List<String>> list =
 Arrays.asList(
   Arrays.asList("Java","Spring"),
   Arrays.asList("Kafka","Docker")
 );
 Data looks like:
 [
 [Java, Spring],
 [Kafka, Docker]
]
This is a List of Lists.

Using map()

list.stream()
    .map(x -> x)
    .forEach(System.out::println);
	
	Output:
	[Java, Spring]
[Kafka, Docker]

Using flatMap()

list.stream()
    .flatMap(Collection::stream)
    .forEach(System.out::println);
Output:	
	Java
Spring
Kafka
Docker

map() is used when one input element produces one output element. flatMap() is used when one input element produces multiple output elements or when dealing with nested collections. flatMap() flattens multiple streams into a single stream. For example, converting List<List<String>> into List<String> is a common use case of flatMap().

map() converts one object into one object, whereas flatMap() converts one object into multiple objects and then flattens them into a single stream. For example, converting List<List<String>> into List<String> is a common use case of flatMap().

Why was Java 8 Date and Time API introduced?
Answer

Before Java 8, Java provided Date and Calendar classes for handling date and time. These APIs had several limitations such as mutability,
lack of thread safety, complex APIs, and difficult date calculations. To overcome these issues, Java 8 introduced the java.time package,
which provides immutable, thread-safe, and easy-to-use date and time classes.
Problems with Old Date API
1. Not Thread Safe
SimpleDateFormat sdf =
       new SimpleDateFormat("dd-MM-yyyy");
       
       SimpleDateFormat is not thread-safe.

In multi-threaded applications:
Incorrect Dates
Data Corruption
Unexpected Results
2. Mutable Objects
Date date = new Date();

date.setDate(25);
Date object can be modified.

This may lead to unexpected behavior.

Java 8 Solution

Java introduced
java.time
package.

Main features:

✅ Immutable

✅ Thread Safe

✅ Better API Design

✅ Easy Date Calculations

✅ Time Zone Support

✅ Better Formatting

How Thread Safety Is Achieved?

All classes are immutable.
LocalDate today =
       LocalDate.now();

LocalDate nextDay =
       today.plusDays(1);
       
       today remains unchanged.

A new object is created.
